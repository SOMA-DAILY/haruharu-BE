## 제품 방향 (2026-08-13 피벗)

**현재 MVP = 운영진 초대코드 모델.** 기존 자동매칭(22:00 배치·남3여3)·코인 경제·PASS 필수 실명인증 모델은 폐기/보류했다. 새 루프:

운영진이 신청폼으로 모집 → 방 생성 + 초대코드 발급 → 관리자가 설정한 참가자가 코드로 입장 → 1시간 슬롯 영상(해당 슬롯 시간대에만 기본 노출, 과거 조회 유지)·방 전체 그룹채팅 → Day3 최종선택(어드민 지정 시각) → 상호 성사 시 1:1 채팅.

- **제거 완료(#451):** 기존 대기열 자동매칭. 큐·FIFO·배치·API·개발 실행·매칭 유도 알림·운영 통계 제거. 최종 상호 선택과 1:1 채팅은 유지한다.
- **티켓 전환(#492):** 코인(유료·리워드 버킷, 보너스 수량, 가입 보너스)을 폐기하고 재화를 티켓 한 종류로 정했다. IAP 결제 시 상품에 정한 수량만큼 지급한다(예: 7,900원 → 1장). 환불 회수는 잔액 0에서 멈추고 못 깎은 수량을 구매 기록에 남긴다. 운영진은 어드민에서 티켓을 직접 지급할 수 있다. 티켓 사용처(방 입장 차감)는 후속 이슈이며, 그 전까지 `haruharu.ticket.enabled`·`haruharu.payment.enabled`는 기본 OFF다.
- **앱 기수 신청(two-way, #510~#521):** 웹 신청 경로(join 폼·송금·공용 코드)는 그대로 두고 앱 신청 경로를 더한다. 운영진이 모집 트랙(예: 서울 대학생)과 트랙별 번호를 매긴 기수(예: 서울 대학생 6기)를 만들어 공개하고(#510), 앱 사용자는 열린 기수에 신청한다(#511): 신청과 동시에 참가권 1장을 쓰고, 방 배정 전에는 언제든 취소해 돌려받는다. 결제 뒤 PASS 를 마치면 신청은 편성 대기로 넘어가고, PASS 성별이 신청 성별과 다르거나 연 나이가 트랙 범위 밖이거나 성별을 해석할 수 없으면 운영진 확인 필요로 남는다(참가권은 그대로, #512). 결제 뒤 설문(유입 경로·친구·신청 마음)은 건너뛰었다가 나중에 낸다. 운영진이 기수를 취소하거나 방에 넣지 못한 신청은 미배정으로 닫혀 참가권을 돌려받고 다음 신청에 우선순위를 받는다. 트랙당 공개(OPEN) 기수는 하나이고, 신청 가능 = OPEN 이면서 신청 기간 안이다. 앱 API 는 `haruharu.cohort.enabled`(기본 OFF)로 막아 둔다.
- **폐기/별도 정리 대상:** daily_upload_reward
- **보류(비활성 잔존):** identity(PASS → 지연인증) · value(가치관)
- **폐기(#482):** 슬롯 기반 자동 미션 배정·카드·활동 수집·성과 집계·후보 카탈로그. 과거 데이터는 보존하며 새 미션 설계는 후속 이슈에서 다룬다. 영상 촬영 슬롯과 운영 글 편성은 유지한다.
- **개편:** room(초대코드·어드민 스케줄·status) · video(슬롯 시간창) · chat(그룹채팅)
- **확정 설계 상세:** 노션 "새 MVP 재설계 — 초대코드 모델" + 메모리 `mvp-pivot-invite-code`

## 인증 아키텍처

```
OAuth2 (Kakao/Apple) → 내부 JWT 발급 → Response Body (access_token, refresh_token)
                                       ↓
                             Spring Security Filter
                                       ↓
                          PASS 지연인증 (보류 — 성별/실명 필요 시점에만 트리거)
```

- AccessToken: 단기 만료, Response Body 반환 → 클라이언트가 Authorization 헤더로 전송
- RefreshToken: 장기 만료, Response Body 반환 + DB 저장 (재사용 탐지)
- 온보딩: **닉네임만** 수집 (성별 미수집 — 필요 시 PASS 지연인증). 옛 프로필 필드(지역·MBTI 등)는 nullable 잔존
- `room_members.gender`는 운영진이 방 구성 시 부여 (admin)

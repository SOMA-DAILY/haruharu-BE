# Modification Policy: 최소 수정 원칙

## 핵심 원칙

**수정 범위는 요청된 기능/버그에 직접 관련된 코드로만 한정한다.**

## 타인 코드

타인이 작성한 코드는 **컴파일 에러 또는 런타임 버그를 일으키는 경우에만** 수정한다.

수정하지 않는 것들 (이유가 있어 보여도 금지):
- 스타일, 포맷팅 차이
- 더 나은 네이밍이 있어 보이는 경우
- 선호하는 패턴과 다른 경우
- 요청받지 않은 성능 개선

## 내 코드

내 코드여도 **현재 태스크와 직접 관련 없는 변경은 하지 않는다.**

PR diff에 아래 항목이 보이면 즉시 revert:
- 관계없는 파일의 포맷/공백 변경
- 요청받지 않은 리팩토링
- 주석 정리, 불필요한 줄 추가/제거

## 예외 (수정 허용)

- 내 변경으로 생긴 orphan import · 미사용 변수 제거
- 컴파일/빌드 실패를 직접 유발하는 인접 코드 수정

## PR 생성 전 체크리스트

- [ ] 변경된 모든 라인이 현재 이슈에 직접 연결된다
- [ ] 타인 코드는 에러 수정 목적으로만 건드렸다
- [ ] 요청받지 않은 리팩토링·포맷 변경이 diff에 없다
